### 3.2 Amendment A1 / Path B disclosure — `hugepages consumed = 0` column

All 15 `huge` rows in the table above show `hugepages consumed = 0` (`hp0 = 4608 → hp1 = 4608`), which triggered 15 warnings in `bench/results/unattended-2026-11-16/stepd/logs/warnings.log` (`WARN: <id> consumed no hugepages (free 4608 -> 4608) - backing not proven`).

**Root cause (harness sampling window, not missing `--hugepages`):**
1. In `bench/stepd/run-stepd.sh` (`run_cell`, lines 160–173), `hp0=$(huge_free)` is sampled **before** spawning `seastar_file_bench` and `hp1=$(huge_free)` is sampled **after** `seastar_file_bench` terminates (and after a 2 s sleep).
2. In seastar (`SeaStarRef/src/core/memory.cc:2016-2025`, `1360-1385`), `--hugepages <path>` is implemented by opening an **unlinked temporary file** (`file_desc::temporary(*hugetlbfs_path)`) in `/mnt/hugepages-juring`, truncating it, and mapping it with `MAP_SHARED | MAP_POPULATE` (`allocate_hugetlbfs_memory`). Because the file is unlinked at creation, the kernel automatically frees all backing hugepages the instant the `seastar_file_bench` process exits — before `hp1` is read.
3. Furthermore, `seastar::memory::configure` has no silent fallback when `hugetlbfs_path` is supplied: if `file_desc::temporary`, `fd.truncate`, or `fd.map(MAP_SHARED | MAP_POPULATE)` fails, seastar throws an exception and aborts startup. Every `huge` run's JSON `argv` confirms `--hugepages /mnt/hugepages-juring` was passed, and Phase 0 + `preflight()` verified `/mnt/hugepages-juring` mounted `rw,pagesize=2M,gid=1000,mode=1770` with 4,608 free 2 MiB pages (9 GiB, sufficient for M3N8's 8 × 1 GiB shards).
4. **Path B disposition:** Under Path B (no benchmark reruns), the 15 `status=ok` `huge` runs are kept as analyzed by the frozen `analyze_stepd.py`, with Amendment A1 recorded in `docs/stepd-design.md` and disclosed here: in-run `/proc/meminfo` `HugePages_Free` delta was not observed directly because sampling was pre/post-process rather than mid-process, while allocation is guaranteed by seastar's non-fallback `memory::configure` path.

## 6. Phase 2 summary — state-controlled write protocol (`docs/m1-write-state-design.md`)

Phase 2 of the unattended campaign (`bench/results/unattended-2026-11-16/write-state/`) executed the pre-registered state-controlled write protocol (`W0 → W1-A → W2 × 5`) on `W7` (4K randwrite QD64) and `W8` (4K randwrite QD128) with JUring `std`, fio `matched`, and fio `matchedbatch`. Full details and per-run classifications are in [`docs/m1-write-report.md` §12](m1-write-report.md):

1. **`w0-control` (600 s post-preconditioning rest, 0 s inter-run rest):** Failed homogeneity (`PILOT_PASS=0`). While all 6 runs had no mid-measurement cliff (`steady=True`), the 600 s rest partially restored SLC burst capacity that exhausted after the first two arms: W7 `juring` ran at `191,497` IOPS, `fio/matched` at `167,671` IOPS, and `fio/matchedbatch` dropped to `91,534` IOPS (`max/min = 2.092 > 1.25`). This directly confirmed the Step A hypothesis that long rests re-create transient burst capacity.
2. **`w1a-continuous` (0 s post-preconditioning rest, 0 s inter-run rest):** Passed (`PILOT_PASS=1`). All 6 runs were `steady=True` and homogeneous within 5.8 % (`W7`: `188,070 / 197,148 / 196,440`, `max/min = 1.048`; `W8`: `185,943 / 196,802 / 196,719`, `max/min = 1.058`). Per the pre-registered adaptivity sequence, `continuous` was selected for the W2 gate campaign and `W1-B` (`brief-idle`) was not needed.
3. **`W2` gate campaign (`w2-g1`..`w2-g5`, 5 generations with `continuous`):** Only **2 of 5 generations (`w2-g1`, `w2-g3`) were valid** (`n_valid = 2 < 4`). In `w2-g2`, `w2-g4`, and `w2-g5`, one or more fio arms transitioned into a deep GC / post-cliff state during their 120 s warmup window (`84,766`, `39,734`, `84,219`, `52,672`, and `162,381` IOPS), violating the intra-generation homogeneity bound (`max/min ≤ 1.25`).
4. **Frozen verdict:** **`INCONCLUSIVE` — only 2 valid generation(s) (`< 4`)**. Under Path B (no benchmark reruns), the M1 write half closes for v1 as `INCONCLUSIVE` (no ranking, no write-parity claim) with a proven hardware cause (sustained multi-generation write pressure drives this consumer NVMe into mid-generation GC/folding states even without inter-run rests).
