ranking, no write-parity claim), both under the Step-A per-cell protocol (§1–§11) and under
the pre-registered state-controlled generation protocol (§12, session 12). The M1 read path
remains PASS (`docs/m1-report.md`).**

files and copied verbatim from
`bench/results/m1-write-2026-11-15/aggregate/m1-write.summary.md`; the reproduce commands

generated by `bench/stepd/write_state_analysis.py` into
`bench/results/unattended-2026-11-16/write-state/analysis/write-state-summary.md`) is
reported in §12.

**The one-paragraph answer.** The full write matrix was measured — W5–W8 (4K randwrite
QD1/16/64/128) and W12–W14 (1M seqwrite QD1/8/32), juring + fio (default/matched/
batching-matched, plus the W7 batching sweep) + seastar — 130 successful measured runs at
the frozen reps (W5/W6/W12–W14 R=3; gate cells W7/W8 R=5). The write-half rule-1 gate
(**PASS iff the one-sided 95 % LB ≥ 0.95 against BOTH fio `matchedbatch` and `matched` at
BOTH W7 and W8**) could not be decided: W7's primary comparator clears the bar only on a
fast-state subset (ratio 0.9628, LB 0.9502, **2 pairs**, fio reps r1/r3/r4 excluded) while
its sensitivity comparator is INCONCLUSIVE; W8 is INCONCLUSIVE against both comparators.
The dominant cause is a **device write-state transition, not rep count**: **36 of the
130 completed measured runs show a 1 s-series write cliff** (within-run burst/steady
ratios from 0.14x to 3.85x — the measured window samples both device states, e.g. W6
fio/default r1 runs 195k IOPS in the burst then 59k in the steady phase), **21 of 34 write cells are unstable
(17 with CV > 10 %)** per methodology D7, and 1M/4K steady states differ between reps on the same
cell. Per methodology D7 ("a write cell with CV > 10 % is reported as unstable, no ranking")
the correct write-half verdict is **INCONCLUSIVE — no ranking**; the previous session's
W7 INCONCLUSIVE at n=3 was therefore not merely a rep-count problem, and adding reps does
not remove the burst/steady mixing.

### 12.1 Hypothesis and frozen protocol

Step A (§5–§6) showed that 300 s inter-rep and 600 s post-preconditioning rests did not prevent device write-state cliffs across reps. Session 12 tested whether measuring all three arms (`juring/std`, `fio-io_uring/matched`, `fio-io_uring/matchedbatch`) back-to-back inside a single preconditioned generation (`--precondition session-once`, 8 chunks = 34,359,738,368 B written before W7) yields single-state, homogeneous generations on `W7` (4K randwrite QD64) and `W8` (4K randwrite QD128) (120 s warmup + 60 s measured per run, 1 s D2 series, CPU 2, JDK 26.0.2, `prlimit --memlock=unlimited:unlimited`).

- **Frozen run classifier (`bench/stepd/write_state_analysis.py`):** A run is `steady=True` (single-state) iff its 60 s measured window (`last min(60, n)` 1 s `write_iops` samples) has `≥ 30` samples and no split where `median(next 10) < 0.70 × median(prev 10)`.
- **Frozen generation validity:** A generation (6 runs: W7 × 3 arms, W8 × 3 arms) is **valid** (`PILOT_PASS=1`) iff all 6 runs are `status=ok` and `steady=True` **and**, within each of W7 and W8, the three arms satisfy `max(IOPS) / min(IOPS) ≤ 1.25` (no burst-vs-steady mixing inside the generation).
- **Pre-registered adaptivity sequence (`docs/m1-write-state-design.md` §4):**
  1. Run pilot **`w0-control`** (`precond_rest=600s, rest=0s`). If valid → run 5-generation W2 gate with `control`.
  2. Else run pilot **`w1a-continuous`** (`precond_rest=0s, rest=0s`). If valid → run 5-generation W2 gate with `continuous`.
  3. Else run pilot **`w1b-briefidle`** (`precond_rest=0s, rest=120s`). If valid → run 5-generation W2 gate with `briefidle`; else stop (`UNRESOLVED`).
- **Frozen W2 gate rule (§5):** Across the 5 W2 generations, keep only valid generations. Require `n_valid ≥ 4`; if `n_valid < 4`, verdict is `INCONCLUSIVE ("only <k> valid generation(s) (< 4)")`.

### 12.4 Why 3 of 5 W2 generations were invalid, and close-out conclusion (Path B)

1. **Why `steady=True` runs still failed generation homogeneity:** Each run executes 120 s of warmup before its 60 s measured window. In `w2-g2` (W7 `fio/matched`: 84.8k IOPS), `w2-g4` (W7 `fio/matchedbatch`: 39.7k; W8 `fio/matched`: 84.2k), and `w2-g5` (W7 `fio/matchedbatch`: 52.7k), the device entered a deep GC / post-cliff folding state *during the 120 s warmup*, so the subsequent 60 s measured window was already flat inside that slow state (no `> 30 %` step inside the measured 60 s, hence `steady=True`), while the other arms in the same generation ran in the ~188k–199k state. The intra-generation homogeneity gate (`max/min ≤ 1.25`) caught every such state split and excluded `w2-g2`, `w2-g4`, and `w2-g5`.
2. **Engine stability vs device state:** Across all 7 generations (14 JUring runs: 7 × W7 + 7 × W8), JUring's own throughput was rock-steady at **188,070–191,497 IOPS** on W7 and **185,943–190,046 IOPS** on W8 (CV 8.1–10.3 % on 1 s device samples), and inside the 3 homogeneous generations (`w1a-continuous`, `w2-g1`, `w2-g3`) `JUring / fio` sits at **0.945–0.958×** (`matched` and `matchedbatch` at W7, `matched` at W8) and **0.945–1.011×** (`matchedbatch` at W8). Because `n_valid = 2 < 4` in W2 (and the W7 `matched` point estimate 0.9459 sits ~0.4 % below the 0.95 bar), the gate is `INCONCLUSIVE`.
3. **Path B close-out for v1:** No further write reruns are performed on this consumer NVMe (`GIGABYTE GP-ASM2NE6100TTTD`), which cannot sustain ≥ 4 homogeneous multi-engine generations (~5.85 TB written in 2 h 22 m) without intermittent controller GC cliffs. For v1, the M1 write half is closed and published as **`INCONCLUSIVE` — no ranking, no write-parity claim**, with both the Step A and Session 12 state-controlled campaigns on the record.
